## Overview

A description and a comment (compact).

<Demo name="overview" title="Read-only" />

## Usage

```tsx
import { Markdown } from "@pp/ui/editor/markdown"

<Markdown>{ticket.body}</Markdown>
<Markdown size="compact">{comment.body}</Markdown>
```

| Prop | |
| --- | --- |
| `children` | The Markdown |
| `size` | `"default"`; `"compact"` for comments (tighter headings); `"reading"` for short text read on its own, such as release notes (15px, looser lines) |
| `blocks` | `"frame"` (blocks with their icons, the default) or `"flat"` (blocks as plain sections) |
| `figmaTarget` | The ticket its Figma links belong to: their names and thumbnails (`EditorServices` `FigmaLinks`), and live embeds for rich links. Without it (previews, hover cards) every Figma link is a chip with the link's text |
| `hideHints` | Hide template hint text in the reading view |
| `onChange` | Receives updated Markdown when the reader ticks a task or detaches a synced section |
| `sectionEditor` | Permissions and navigation for managing synced sections |

## Rules

### One look for reading and editing

`Markdown` and the editor share their styles (`.prose-md`, in `prose.css`), and the same mentions, attachments, blocks, Figma and Paper chips and code highlighting, so switching a description into edit mode moves nothing.

Code blocks render their text and line numbers immediately. A language label starts loading the tokenizer, and the colors appear in place once it is ready.

### Checkboxes are the Checkbox

Task lists render the Checkbox component. A description with `onChange` lets readers tick items directly, including in synced sections. Other surfaces show read-only checkboxes.

### Links show their page, unsafe ones are dropped

Links get their page's title and favicon like in the editor. Unsafe URLs (`javascript:` and the like) are dropped, while mention and attachment links stay.
