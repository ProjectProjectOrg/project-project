## Overview

Every size the app uses, four different seeds, stacks at three sizes and the icon fallback for agents and system events.

<Demo name="overview" title="All states" />

## Usage

Use `MemberAvatar` for people. It shows the member's photo when they have one, and otherwise an orb generated from their id. Use `AvatarStack` for a row of people.

```tsx
import { AvatarStack, MemberAvatar } from "@pp/ui/member-avatar"

<MemberAvatar member={assignee} size={20} />
<MemberAvatar member={user} size={64} label={user.name} />
<AvatarStack subjects={ticket.assignees} size={24} max={4} />
```

| Prop     | Type                                       | Default |
| -------- | ------------------------------------------ | ------- |
| `member` | `{ id, name?, email?, image? }`            |         |
| `size`   | `number` (px)                              | `20`    |
| `label`  | `string`                                   |         |

Where an avatar changes in front of the person (picking a profile photo, a name being typed), use `DissolveAvatar` from `@pp/ui/dissolve-avatar`: it takes the same `member`, `size` and `label`, and dithers from the old look to the new one.

`AvatarStack` takes `subjects`, `size` and `max` (default 4), and shows `+n` for the rest. Hovering or focusing the `+n` shows a tooltip listing the people it stands for, each with their avatar and name; `countTooltip={false}` turns that off where the stack sits inside a control with a tooltip of its own (a trigger can't nest in a button). `animated` grows and fades people in and out as they join or leave instead of popping (a stack that follows a selection), and `overlap` sets how far each avatar tucks under the one before it, in px (8 by default).

## Rules

### Squircle with a lit edge

Avatars use the app's squircle corners (`corner-shape: squircle` at a 50% radius) and fall back to a circle. A 1px hairline sits inside the edge, with a soft light along the top: white at 55% in light mode and 22% in dark. The orb reads as lit from above with no drop shadow.

### Initials from 20px

From 24px up, the orb carries the member's initials (two letters); at 20px, only the first letter, since two don't fit. Either way they're drawn in an ink tuned per hue and theme: at least 5:1 against every tone of the orb in both themes, so it meets WCAG AA contrast (4.5:1) wherever a letter lands. In a stack, the initials centre in the part the next avatar's cutout leaves visible.

Below 20px the letters are too small to read on a dithered orb, so 16px and 18px avatars show only the orb.

### Below 20px, always show the name

An avatar smaller than 20px has no initials, so it can't identify a person on its own. Put the member's name next to it: an assignee chip, an activity line, a "flagged by" row. Where there's no room for a name, use 20px or larger so an initial shows.

### Stacks cut a gap, they don't paint one

Each avatar in a stack has a squircle cut out where the next one overlaps it, 2px larger than the avatar. The orbs are translucent, so the cut keeps them from showing through each other, and the gap shows the real surface underneath rather than a painted ring.

### Accessible name

An avatar next to the person's name, or inside a labelled control, is hidden from assistive tech. An avatar that stands alone takes `label`, usually the member's name, and becomes an image with that name. The initials are drawn with generated content, not text, so they never end up in the name of a button that wraps the avatar.

### Changes dither in

`DissolveAvatar` fills the new avatar in through an ordered (Bayer) dither, the same 4×4 pattern the orbs are painted with: 8 steps over 320ms, linear, the old avatar showing through the cells not yet covered. The cells are 2, 3 or 4px depending on the avatar's size, like the orb's own dither, so the transition looks like part of the avatar rather than a fade laid over it. A change mid-transition starts a new layer on top instead of restarting, so typing a name keeps dissolving smoothly. A new photo waits until it has decoded. With reduced motion it swaps at once.

## Explore

Type a name, or roll a random one. Once typing pauses (250ms), the orb follows: it is seeded by the name, so every name gets its own; the line under it lists what was drawn. Each change dithers in, at every size and next to a name.
