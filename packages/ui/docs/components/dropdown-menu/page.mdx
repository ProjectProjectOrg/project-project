## Overview

Every kind of row and state in one menu: the highlight resting on the first item, plain items with icons and shortcuts, a disabled item, checkbox and radio choices, a submenu, a destructive action, and confirm items: live, armed, busy and failed. The busy one holds the menu open, as it would while a delete runs. Hover, press or use the arrow keys to move the highlight.

## Usage

```tsx
import {
  DropdownMenu,
  DropdownMenuCheckboxItem,
  DropdownMenuContent,
  DropdownMenuTrigger
} from "@pp/ui/dropdown-menu"

<DropdownMenu>
  <DropdownMenuTrigger render={<Button variant="secondary" />}>
    {m.tickets_filters_tags()}
  </DropdownMenuTrigger>
  <DropdownMenuContent className="w-56">
    {tags.map((tag) => (
      <DropdownMenuCheckboxItem
        key={tag.name}
        label={tag.name}
        checked={selected.has(tag.name)}
        closeOnClick={false}
        onCheckedChange={() => toggle(tag.name)}
      >
        <TagDot color={tag.color} />
        {tag.name}
      </DropdownMenuCheckboxItem>
    ))}
  </DropdownMenuContent>
</DropdownMenu>
```

A row's children are its marker (an icon, dot or avatar), its label and an optional count with `data-menu-meta`. The tick slot is added for you.

### Confirm items

Any menu action that can't be undone or affects other people (delete, remove, disconnect, transfer ownership, cancel an invite) is a `DropdownMenuConfirmItem`. It confirms in place: no popover, no dialog. Everything below is built in; what the call site supplies is the four labels and an `onConfirm` that reports failure.

```tsx
<DropdownMenuConfirmItem
  icon={<Trash2 className="size-4" strokeWidth={1.75} />}
  label={m.sprints_delete_button()} // "Delete sprint"
  confirmLabel={m.sprints_delete_confirm_title()} // "Delete this sprint?"
  busyLabel={m.common_deleting_button()} // "Deleting…"
  describeError={describeCause} // "Couldn't delete the sprint."
  onConfirm={onDelete} // returns the mutation's Exit
/>
```

| Prop             | Type                                                    | Default         |
| ---------------- | ------------------------------------------------------- | --------------- |
| `label`          | `string`, the action                                    |                 |
| `confirmLabel`   | `string`, the question the armed item asks              |                 |
| `busyLabel`      | `string`, the verb in progress                          |                 |
| `describeError`  | `(cause: Cause<E>) => string`                           |                 |
| `onConfirm`      | `() => Promise<Outcome> \| Outcome`                     |                 |
| `icon`           | `ReactNode`                                             |                 |
| `tone`           | `"destructive" \| "neutral"` (transfer ownership)       | `"destructive"` |
| `quiet`          | `boolean`, plain until armed (a list of targets)        | `false`         |
| `timeout`        | seconds, or `false`, for the countdown and the error     | `4`             |
| `closeOnConfirm` | `boolean`                                               | `true`          |
| `disabled`       | `boolean`                                               | `false`         |

`Outcome` is nothing or `true` (done), `false` (quietly back to armed), or an Effect `Exit`: a failure shows `describeError(cause)`. Return the mutation's `Exit` (`useAtomSet(…, { mode: "promiseExit" })`), so failures show in the item.

#### States

| State     | Label                    | Icon            | Fill                                   | Menu                                  | Leaves when                                   |
| --------- | ------------------------ | --------------- | -------------------------------------- | ------------------------------------- | --------------------------------------------- |
| Idle      | `label`                  | `icon`          | none (highlight on hover)              | normal                                | first click arms it                           |
| Armed     | rolls to `confirmLabel`  | `icon`          | countdown, drawn even without hover    | stays open                            | second click, or 4s pass (back to idle)       |
| Busy      | rolls to `busyLabel`     | logo loader     | none                                   | held open: no Escape, outside click   | `onConfirm` settles                           |
| Done      |                          |                 |                                        | closes (`closeOnConfirm`)             |                                               |
| Failed    | rolls to the error       | alert           | none (an unseen timer runs)            | stays open                            | a click retries; 4s pass (back to idle)       |

Every label change rolls through TextSwap and every icon change crossfades, so the row never jumps. Pointer over the item or keyboard focus on it holds both timers, so keyboard and screen reader users never run out of time; the new label is announced politely, and the error as an alert.

#### Wording

| Label          | Write                                      | Example                      | Not                 |
| -------------- | ------------------------------------------ | ---------------------------- | ------------------- |
| `label`        | the verb and the thing                     | Delete sprint                | Delete…             |
| `confirmLabel` | a question naming what goes                | Delete this sprint?          | Are you sure?       |
| `busyLabel`    | the verb in progress, with an ellipsis      | Deleting…                    | Loading…, Please wait |
| error          | what failed, from `describeError`          | Couldn't delete the sprint.  | Error, Something went wrong |

#### Checklist

- Return the mutation's `Exit` from `onConfirm`; a thrown or swallowed error leaves the person guessing.
- Pass a `busyLabel` that says what's happening, not the question again.
- Don't close the menu, navigate away or clear a selection before `onConfirm` resolves; do it inside `onConfirm` after success, and let the item close the menu.
- Put destructive items last, after a separator.
- A choice beyond yes or no is more items, not a form: a second item (delete, or delete with its sub-tickets), or a submenu of `quiet` items (move its tickets to this status, then delete).
- Transferring ownership and other non-destructive but serious actions use `tone="neutral"`.
- The page's own buttons confirm with Confirm button's capsule instead; never a popover or dialog.

## Rules

### Pickers are menus, selects are form fields

A value you pick while working (status, priority, assignee, type, estimate, a toolbar's grouping or ordering, the org and project switchers) is a menu with a `DropdownMenuRadioGroup`, so every picker numbers its rows, takes actions after its choices and nests as a submenu. `Select` is for a value that belongs to a form or a settings row.

### Multi-select rows use `DropdownMenuCheckboxItem`

A row that toggles a choice inside a menu is a `menuitemcheckbox`, never a checkbox nested in a menu item. The menu stays open while you toggle, through `closeOnClick={false}`.

### Checked rows step forward, unchecked rows stay plain

A checked row gets a leading mark and a full-colour, semibold label. Unchecked rows are ordinary rows: icons and avatars in full colour, labels in the menu text colour (`--menu-foreground`) and keys muted. Labels meet WCAG AA comfortably: 9.2:1 on the dark menu fill (8.0:1 on a raised one), 6.0:1 on the light one. Fading is kept for disabled rows, so "not chosen" never reads as "not available". Screen readers hear the state from `aria-checked`.

### Some of a selection is mixed

A checkbox row that speaks for several things at once (labels on a selection of tickets) has a third state: `mixed`, set on some of them. It shows a dash where the check goes, keeps its label and icon at full strength, and reads as "mixed" to screen readers. A click puts it on all of them, then on none, then back to mixed. Keep `checked` false while it's mixed.

### Radio rows keep the mark's slot

Radio rows reserve the 16px leading slot, chosen or not, so picking another option never shifts the labels. A checkbox row has no slot until it is ticked: ticking opens the slot and draws the tick, and unticking rewinds it.

### Radio rows match checkbox rows

A radio row behaves like a checkbox row: the chosen option gets the leading slot, a full-colour semibold label and a dot instead of a tick. The dot springs in from nothing, and shrinks away quickly when another option is chosen. Single and multiple choice then read the same way, and only the mark tells them apart.

### Shortcuts are keys, inset like a trailing icon

A row's shortcut is `DropdownMenuShortcut keys="…"`: small Kbd keys (⌘ ⇧ ↑ on a Mac, Ctrl Shift ↑ elsewhere), the same keys as ⌘K, tooltips and buttons. The last key sits 9px from the highlight's end, the same as from its top and bottom. The keys are hidden from screen readers; the item carries `aria-keyshortcuts`. Radio rows numbered 1 to 9 (then 0) pick on that digit, and carry it as `aria-keyshortcuts` the same way. In a menu with a search, a digit picks while the search is empty and searches once you've typed, so a search can't start with a digit.

### Pickers open on the chosen row

A menu whose first row is a choice (a status picker, a priority submenu) is a picker: with nothing hovered, the highlight rests on the checked row, and a keyboard open starts there too, so arrow keys step on from the current value. An action menu with a few choices further down starts at its top like any other menu.

### Rows are lit in dark mode

A row's label is weight 450, a hair above body text, so short labels hold up on the menu fill. Its text at rest is `--menu-foreground`: in dark it sits between the muted grey and the foreground (`oklch(0.86 0 0)`), because grey on the raised menu fill read washed out and full white was too loud; light keeps it muted. The highlighted row takes the full foreground. Icons stay muted until the row is highlighted. A destructive row is red in both themes.

### Submenus open at once and fade out

A submenu opens as the pointer reaches its row, so sweeping down a menu shows each one it passes. Their contents mount hidden just after the menu paints, so opening one is a visibility flip; a submenu whose contents load something on mount (a branch search) passes `lazy` to `DropdownMenuSubContent` and mounts when it opens. Base UI shows a submenu a frame after it opens, once it is placed, so the one being left fades out over 80ms meanwhile and the menu never shows a frame without one. Escape and keyboard closes skip the fade (`data-instant`). The highlight glides between rows on `transitions.snap` (40ms) and follows the pointer itself, not the row Base UI has marked, so it never trails.

`DropdownMenuSub` holds the submenu's open state and its row opens it on hover, with Base UI's own `openOnHover` off: that one stops the menu's other rows taking the pointer for as long as the submenu is open, which costs two pointer moves per switch. `menu-highlight.tsx` blocks the other rows only while the pointer is heading for the open submenu (`data-menu-aiming`), so a diagonal move into it still crosses them safely. `openOnHover={false}` on a `DropdownMenuSubTrigger` keeps a submenu to click and keyboard.

### Submenus line up with their row

A submenu opens 2px beside the menu, with its first row level with the row that opened it; its own top edge sits 5px higher, by its padding. The arrow on a submenu row ends where a shortcut's last key does, 9px from the highlight.

### A pick closes the menu as it was

A radio row that closes the menu (`closeOnClick`) doesn't move the dot on its way out: the menu fades out showing the selection it opened with, and the new value shows on the page. A selection changing inside a menu that is leaving reads as two events at once. The next open shows the new value. Escape and an outside click close the same way.

A pick from the keyboard (Enter, or a row's digit) closes the menu in 80ms instead of 150ms, the submenu's fade: the hand is already on the next key, and a full fade reads as lag, while no fade at all leaves the trigger's new value rolling in on its own. A digit also moves the highlight to its row first, so a menu that stays open shows the pick where you're looking.

### A keyboard close returns focus to the trigger

`finalFocus={false}` keeps focus off the trigger after a pointer close, so a mouse pick doesn't leave a ring or its tooltip on the chip. A close from the keyboard (Escape, or a pick with Enter or a digit) still returns focus to the trigger, so Tab carries on from there instead of the top of the page.

### Hover and press match the buttons

The highlight that glides between rows takes `--menu-hover` on hover and `--menu-active` while pressed: a fixed lightness step from the popup's fill (see Interaction states), so they show on the plain and the raised menu alike. Destructive rows take the destructive button's: `--destructive-light`, then its hover mix while pressed. Selects and the mention menu share the same highlight.

### Menu actions confirm in place

A menu is already a small surface the person is looking at, so a delete confirms right where they clicked. A popover or dialog would move their eyes and their pointer for a yes or no; the app has no dialogs at all.

### The armed fill is the countdown

An armed item left alone is a loaded button, so it disarms after 4 seconds, and its fill shows the time left. The fill stays drawn when the pointer leaves, because it's the item's state, not a hover effect. It is a step darker than the destructive hover, so it still reads with the highlight under it. It is Button's countdown (`lib/countdown`), so both read the same.

### A running action holds the menu open

While `onConfirm` runs, Escape, an outside click, another item and hovering off a submenu can't close the menu, so the person sees the result. The hold is counted, so two running items don't release each other, and an item that goes away releases its own.

### Failures say so twice, then step back

The error rolls in and the icon turns into an alert, because the label is already red and colour alone wouldn't mark it. After 4 seconds it goes back to its label, so a stale error doesn't sit in the menu; hover or focus holds it while it's being read.
