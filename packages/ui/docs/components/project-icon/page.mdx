## Overview

Four projects large, the Atlas tile at every size the app uses, and the emoji, uploaded-image and saving states.

<Demo name="overview" title="All states" />

## Explore

Generated tiles for sixteen seeds. Each seed picks a surface pattern, a light and a texture; the project's colour sets the palette. Switch the tone to repaint the same seeds in one hue, the orbs' three hues, or grey, and roll new seeds to see more.

## Usage

```tsx
import { ProjectIcon } from "@pp/ui/project-icon"

<ProjectIcon
  seed={project.slug}
  color={project.color}
  icon={project.icon}
  image={project.iconImage ? <ProjectIconImage project={project} size={28} /> : undefined}
  size={28}
/>
```

| Prop      | Type                                                      | Default  |
| --------- | --------------------------------------------------------- | -------- |
| `seed`    | `string`, what the backdrop is generated from (the slug)  | required |
| `color`   | `string`, the project's colour as `#rrggbb`               | required |
| `tone`    | `"mono" \| "multi" \| "gray"`, how the colour is used | `"mono"` |
| `size`    | `number`, the side in px                                  | required |
| `icon`    | `string`, the emoji                                       |          |
| `image`   | `ReactNode`, an uploaded icon shown instead of the emoji   |          |
| `waiting` | `boolean`, pulses while the icon saves                    | `false`  |
| `label`   | `string`, the project's name when the tile stands alone   |          |

## Rules

### Generated like the avatars

The backdrop is a generated tile (`lib/projectTile`), built like the member orbs (`lib/orbAvatar`): one seed picks a surface pattern from the orbs' set, a light (diagonal, side or flat), a zoom, a texture and sometimes a glow, and the result is painted through the same 4×4 ordered dither at the avatars' cell sizes. The colours come from the same place as the orbs' (`lib/ditherPalette`): five translucent steps (50% down to 20%), so the tile reads light, never heavy. They're laid over a card-coloured base, not over whatever is behind the tile, so a tile looks the same in the rail's tinted items, on cards and in rows. A wheel colour is used exactly as the wheel defines it. `mono` keeps every step on the project's hue; `multi` ignores the project's colour and takes all three hues from the seed, exactly as a member orb does, so it's the same tile whatever accent was picked before; `gray` drops the chroma. The tone never changes the pattern, so a project keeps its tile when its tone changes. Two projects with the same colour still look different. Painted tiles are cached per seed, colour, size and pixel density.

### The emoji is centred on the tile

The emoji is 62% of the side, at line-height 1, centred by the tile's grid at its real width. That matters at small sizes: below about 14px the emoji font draws its smallest bitmap, up to 30% wider than the font size, so a glyph box the size of the font pushes the emoji off to the right (the old 16px tile's drift). Vertically, at line-height 1, the glyph already sits within 5% of the centre, so it gets no nudge.

### Shadows by size

From 24px up the emoji gets the layered drop shadow that lifts it off the dither; below that a single half-pixel shadow, since a blur at that size only muddies it.

### Shape

Corners at about 28% of the side (`projectIconRadius`), squircled (`corner-squircle`); a container that wraps the tile, like the rail item, takes the same radius instead of rounding the tile to its own, with the avatars' hairline edge and top light (`avatarEdgeClass`) instead of a drop shadow, so tiles and member orbs sit side by side as one family. Without a label the tile is hidden from assistive tech, because the project's name is always next to it.
