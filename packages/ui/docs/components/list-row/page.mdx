## Overview

The rows a list shows: interactive ones first (hover a row, tick its checkbox), then each state pinned. The fields here are stand-ins; in the app they are menus.

<Demo name="overview" title="All states" />

## Usage

The list sets `listGridClassName` on the element that holds its rows; each `ListRow` uses that grid to align status, key, estimate and assignee across rows and sections. The title and chips share the space between them.

```tsx
import { ItemLink } from "@pp/ui/item-link"
import { ListRow, ListRowTitle, listGridClassName } from "@pp/ui/list-row"
import { TicketKey } from "@pp/ui/ticket-key"

<div className={listGridClassName}>
  <ListRow
    selected={selected}
    disabled={!editable}
    link={
      <ItemLink
        render={<Link to="/orgs/$orgSlug/projects/$slug/tickets/$id" params={…} />}
        aria-label={`${ticket.id} ${ticket.title}`}
      />
    }
    lead={<RowCheckbox … />}
    status={<StatusButton … />}
    priority={<PriorityButton … />}
    ticketKey={<TicketKey value={ticket.id} pending={pending} />}
    title={<ListRowTitle>{ticket.title}</ListRowTitle>}
    trailing={<TagChips … />}
    estimate={<EstimateBadgeTrigger … />}
    assignee={<AssigneeField … />}
  />
</div>
```

| Prop | Type | What it does |
| --- | --- | --- |
| `link` | `ReactNode` | An `ItemLink` stretched over the row, so a click anywhere opens the ticket |
| `lead` | `ReactNode` | The first column: the selection checkbox |
| `status`, `priority` | `ReactNode` | The two icon columns, each `--list-icon` wide |
| `ticketKey` | `ReactNode` | A `TicketKey`; give it `min-w-(--ticket-key-width)` so keys line up. Leave out with `priority` for a row that isn't a ticket |
| `title` | `ReactNode` | The title column, which takes the remaining width: the parent (`ListRowCrumbs`), `ListRowTitle`, inline chips |
| `trailing` | `ReactNode` | Chips at the end: tags, git, relations, sprint |
| `estimate`, `assignee` | `ReactNode` | The last two columns; the assignee hides on narrow screens |
| `selected` | `boolean` | Tinted fill for a ticket in the multi-select |
| `disabled` | `boolean` | Disables the row's fields, for someone who can only look |
| `variant` | `"standalone" \| "embedded"` | `embedded` drops the hover and corners, for a row inside a card |

`ListRowTitle` takes `variant="quiet"` for the regular weight instead of semibold, for rows that sit under a heading that should lead, such as the sub-tickets on a ticket's page.

Parts used with it: `ItemLink` (`@pp/ui/item-link`), `TicketKey` (`@pp/ui/ticket-key`), `ProgressCount` (`@pp/ui/progress-count`) and `Chip` (`@pp/ui/chip`), which the board card shares.

## Rules

### One parent, folded to its key when tight

A ticket has at most one parent: its epic, or the ticket it is a sub-ticket of (a sub-ticket has no sub-tickets, so there is never a second level). `ListRowCrumbs` shows it before the title with a slash. When the title would be cut, the parent folds to its key (ATL-22), whose preview still says what it is; below an 8rem title the key drops out, so the title never disappears behind it.

### The whole row is the link

A click anywhere on the row opens the ticket, through one `ItemLink` stretched under the row's content. The row's own controls (status, priority, assignee, chips) sit above it on `z-20`, so they still take their own clicks. Keyboard users tab to the link once per row; the link's inset ring is the row's focus.

### Rows that aren't tickets

A row for something other than a ticket (a sprint on the Sprints page) leaves out `priority` and `ticketKey`. Those two columns then go to the title, so it starts 8px after the icon, where a section header's label starts, instead of after two empty columns' gaps.

### One grid for the whole list

Rows are subgrids of the list's grid, so a long key or a wide estimate in one row widens that column for every row, and the columns never zigzag. The leading widths are CSS variables (`--list-lead`, `--list-icon`, `--list-row-gap`, `--list-lead-gap`) so section headers can line up with the rows under them. `--list-pad-start` (5px) sets the start padding of rows and headers so the lead column (checkbox, chevron) centres on the icons of the fields above the list, the composer and search, which sit 17px in.

### One highlight glides between rows

Inside a `ListHoverScope` (the backlog wraps all its sections in one) the hover is a single highlight that slides from row to row under the pointer, like the sidebar's, instead of each row lighting up on its own. It holds across the 4px gap between rows but drops over a section header, so a header never lights the row next to it. While a row has a menu or preview card open, the highlight stays on that row when the pointer moves into the popup, and the row doesn't add a fill of its own, so it's never lit twice. Outside a scope (a sub-ticket list, the dashboard) a row fills itself.

### Hover is instant, keyboard navigation has no fade

The row fills on hover without a delay. While someone moves through the list with the arrow keys (`data-keyboard-navigation` on the list) the hover is off and the fill moves without a transition, so it follows the keys instead of trailing behind.

### 40px rows, the title leads

A row is 40px: 24px fields and 8px above and below (`listRowHeight`, which the virtualized backlog uses for its row tracks). Its corners are half its height (20px) with `--button-corner`, like a button, and the hover highlight and focus ring share them. Everything but the title is quiet: chips are flat muted text with no outline (`Chip`), the estimate is a bare number with its unit icon, and priority is signal bars (one, two or three lit) in the priority's colour.

### Tags fold before the title shrinks

Each title takes the space left by its own row’s chips and keeps at least 10rem, and the list grid is the `list` container. Below 48rem a row's tags fold into one chip: every tag's dot and the count (`ChipDots` on a `show="narrow"` chip), with the names on hover. The named chips and their "+N" take `show="wide"`. If the chips still don't fit, whole chips drop out rather than being cut in half.

### Placeholders wait for the hover

The selection checkbox and an empty assignee only show while the row is hovered, focused or has a menu open, so a list of unassigned tickets doesn't fill a column with empty faces. Both are 24px targets (the checkbox a 16px box, the face 20px), so they meet the target size without a pseudo-element hit area.

### Pending ticket keys

A small skeleton shimmers in the key slot until the create response supplies the permanent ID. The key replaces it immediately, even while sprint assignment is pending. With reduced motion the skeleton stays still.
