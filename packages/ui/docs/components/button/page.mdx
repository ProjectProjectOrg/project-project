## Overview

Every main variant, size and state. Hover, pressed and focus are pinned with `data-force`. Layout-specific variants (`appearance-row`, `selection-card`, `dropzone`, `artwork-option`, `image-option`) are left out here. `dither` is shown in the sprint rail below too.

## Usage

Pass icons as components through `leadingIcon` and `trailingIcon`, so the button sizes and pads them. Icon-only buttons take the icon as a child and need an `aria-label`.

```tsx
import { Button } from "@pp/ui/button"
import { Plus } from "@pp/ui/icons"

<Button variant="primary" leadingIcon={Plus} onClick={openCreate}>
  {m.tickets_create_button()}
</Button>

<Button render={<Link to="/" />} variant="tertiary" size="lg">
  {m.error_page_home_link()}
</Button>
```

| Prop                           | Type                                                                                                                   | Default     |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------- | ----------- |
| `variant`                      | `"primary" \| "secondary" \| "tertiary" \| "destructive" \| "ghost" \| …`                                              | `"primary"` |
| `tone`                         | `"muted" \| "strong"`, ghost only: muted text that brightens on hover, or full foreground for triggers showing a value. `"destructive"`: a remove action, red on hover (ghost, overlay) or at rest (tertiary). `"warning" \| "error"`: a control reporting a problem, coloured in every state | `"muted"`   |
| `size`                         | `"xs" \| "compact" \| "sm" \| "inline" \| "md" \| "lg" \| "icon-xs" \| "icon-sm" \| "icon" \| "icon-lg" \| …`                      | `"md"`      |
| `leadingIcon` / `trailingIcon` | `IconComponent`                                                                                                        |             |
| `loading`                      | `boolean`                                                                                                              | `false`     |
| `bleed`                        | `"start" \| "end"`                                                                                                     |             |
| `render`                       | `useRender.RenderProp`                                                                                                 |             |
| `dither*`                      | colours, stops, matrix and pixel size for the `dither` variant                                                         |             |
| `countdown`                    | `{ seconds, onElapsed, delay? }`: the fill drains over `seconds`, then `onElapsed` runs                                |             |

Every other prop goes to the rendered `button`.

## Rules

### A leading icon or avatar sits closer to the edge

The icon side gets about three quarters of the text side's padding, because an icon or avatar carries less weight than a word. `leadingIcon` and `trailingIcon` get it, and so does an icon or avatar passed as the first child with more after it (a member's avatar and name in a ghost trigger), through the `lead` variant in `theme.css`. A button that holds only an icon takes an icon size, which has no padding to shift. CSS can't see bare text, so a label followed by an icon (`Sprint <ChevronDown />`) goes in a `<span>` or uses `trailingIcon`; otherwise the icon reads as the first child.

### Loading swaps in place

`loading` lays the logo loader over the label instead of replacing it: the label fades and blurs out (180ms, `ease-standard`) while the loader fades in from 60% scale, and the reverse when it ends. The label stays laid out, so the button's width never changes. A button that passes `loading` at all, `true` or `false`, keeps that structure either way, so the swap can animate; buttons that never load keep their content unwrapped. With reduced motion, only the fades play.

### Countdown: the fill is the timer

A button that will act or go away by itself shows how long is left in its own fill: the fill drains toward the start over `seconds`, over a tertiary base so the label stays readable, then `onElapsed` runs. `delay` waits first, for example until an entrance has landed. Hovering the button, or an ancestor marked `data-countdown-hold`, holds it; so does keyboard focus in either, for as long as it stays, so keyboard and screen reader users never run out of time (WCAG 2.2.1). A disabled or loading button holds it too. Use it on destructive and secondary: primary's light label doesn't read once its ink fill drains. The same countdown (`lib/countdown`, the `.countdown` class) runs in Confirm button's capsule and in Dropdown menu's confirm item.

### Popover footer

A ghost Cancel next to a destructive confirm, as in Confirm button's stacked step from a menu. The app has no dialogs; these footers sit in popovers.

### Countdown

`countdown` on its own: Delete runs out after 4 seconds, Keep editing after 6. Hover either button, or the space between them, to hold both.

### Settings group

Tertiary's home: row actions inside a settings group. A settings group is a `tertiary-tiles` group, where tertiary is a flat `--surface-3` tile with no border. Everywhere else it takes half of secondary's tint, one step quieter than secondary.

<Demo name="settings-group" title="Settings rows" />

### On a banner

Every fill is solid: worked out from the surface the button sits on, never see-through, so a project banner's dithered image doesn't show through secondary, tertiary or a ghost hover.

<Demo name="on-a-banner" title="On a banner" />

### Dither: New sprint

The `dither` variant: the primary colour dithered into the surface behind it, so the button fades into the rail. Hover slides the dither from 0.7 to 0.5 of the width. It takes the same squircle as every other button.
