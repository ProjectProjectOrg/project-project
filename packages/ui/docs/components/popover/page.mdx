## Overview

The popover open on its surface, with a title, a close button, body text and actions. Click the trigger to close and reopen it.

## Usage

```tsx
import { Popover, PopoverContent, PopoverTrigger } from "@pp/ui/popover"

export function ViewOptions() {
  return (
    <Popover>
      <PopoverTrigger
        render={
          <ToolbarButton aria-label={m.tickets_view_options_label()}>
            <SlidersHorizontal className="size-4" strokeWidth={1.75} />
            {m.tickets_view_options_label()}
          </ToolbarButton>
        }
      />
      <PopoverContent
        aria-label={m.tickets_view_options_label()}
        align="end"
        side="bottom"
        className="w-80 p-0"
      >
        <div className="space-y-2 p-3">
          <Ordering />
          <DisplayProperties />
        </div>
      </PopoverContent>
    </Popover>
  )
}
```

`PopoverContent` wraps Base UI's portal, positioner and popup, so placement props go straight on it. `PopoverTitle` and `PopoverClose` pass through to Base UI.

`PopoverFooter` is a bar for the bottom of a sectioned popover (`p-0`), placed after the scrolling body. It folds in while `show` is true:

```tsx
<PopoverFooter show={!isDefault}>
  <Button variant="ghost" size="sm" onClick={reset}>
    {m.tickets_view_options_reset_view()}
  </Button>
</PopoverFooter>
```

| Prop                 | Type                                     | Default    |
| -------------------- | ---------------------------------------- | ---------- |
| `side`               | `"top" \| "bottom" \| "left" \| "right"` | `"bottom"` |
| `align`              | `"start" \| "center" \| "end"`           | `"end"`    |
| `sideOffset`         | `number`                                 | `4`        |
| `alignOffset`        | `number`                                 |            |
| `anchor`             | element, ref or virtual element          | trigger    |
| `collisionAvoidance` | Base UI collision settings               |            |
| `collisionBoundary`  | `Element \| "clipping-ancestors"`        |            |
| `collisionPadding`   | `number`                                 |            |
| `keepMounted`        | `boolean` (keep the popup in the DOM)    | `false`    |
| `surface`            | `"popup" \| "hover"`: a click-opened panel, or the hover card's skin and 14px corners for content shown on hover | `"popup"` |

## Rules

### One surface for every popup

Popover, dropdown menu, select and context menu all use `popupSurfaceClass` from `menu-styles.ts`: the tooltip's raised skin (the `--tooltip` fill, the `--tooltip-edge` hairline and top light) with 19px squircle corners. Tooltips and hover cards wear the same skin through the tooltip host, so whatever floats reads as one family. Restyle the shared class, never one popup.

A popup opened from inside another (a select in View options) steps one level up, to `--tooltip-raised` (lighter in both themes: `0.33` over `0.29` in dark, `0.996` over `0.99` in light), so it floats above its parent instead of reading as a cut-out of it. Popovers, menus and selects do this themselves through `PopupLayerContext`.

### No shadows

The raised fill and the hairline separate the panel from the page, in light and dark. Shadows stay off popups, including callsite overrides such as `shadow-md`.

### Same motion as menus

Opening fades in, scales up from 95% and slides 8px out from the trigger's side over 150ms, scaled from the trigger's corner (`--transform-origin`). Closing fades and scales back to 95%. Reduced motion turns the animation off.

### 12px padding, or none

The default padding is 12px. Content that brings its own sections and dividers, like View options or the sprint creator, passes `p-0` and pads each section itself, so dividers run edge to edge.

### Footers fold in

A `PopoverFooter` appears only when it has something to offer, such as a reset once a view differs from the default. It grows from zero height and fades in over 220ms (`transitions.layout`), and folds out over 180ms (`transitions.presence`), so the popover gets taller and shorter with it rather than jumping. A footer already showing when the popover opens is just there. Reduced motion keeps only the fade.

The footer sits outside the scrolling body, so it stays put while the body scrolls. Its top hairline (`border-border/60`, the same as the section dividers) runs edge to edge, and its actions sit on the right. Reset is a small ghost button.

## Examples

### View options

The ticket toolbar's View options popover in the backlog list: the list and board switch, grouping and ordering pickers with a sort direction button, and display property chips. Once anything differs from the default, the trigger shows how many settings changed and a footer folds in to reset the view.

### New sprint

The sprints overview's "New sprint" button opens the sprint composer: a whole form in a popover, laid out like every composer (title and description on the card, dates and actions on the tray), with the date range picker as a second popover nested inside it. Focus stays trapped in the form, and the nested calendar closes on its own without closing the form.

### Estimate

The estimate property on a ticket page or board card. One field, a live reading of what you typed that blurs between values, and Clear and Save. An invalid entry replaces the reading with the error, so nothing below it moves.
