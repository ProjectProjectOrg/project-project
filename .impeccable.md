## Design Context

### Users

ProjectProject is a markdown-first PM tool for engineers running it on a homelab — primarily a single-user install, multi-user-capable. The audience is technical: people who would rather grep a folder than click through a kanban board. They're managing tickets, branches, PRs, and project docs alongside actual coding work, often switching between this and a code editor.

Viewing context is mixed: daytime at a desk and late-night in a dim room are equally common. Light and dark themes are first-class peers, not "default + alternate."

### Brand Personality

Three words: **clear, simple, lightweight.**

Concretely: an engineer's tool that gets out of the way. No decoration for decoration's sake. Information dense but never noisy. The product respects the reader's attention — every pixel is either functional or deliberately quiet.

### Aesthetic Direction

**Reference:** Linear. The bar is Linear-grade restraint: tight type, generous-but-not-wasteful spacing, fast feel, no visible chrome bloat.

**Anti-references:** Jira, Azure DevOps, Trello. Avoid everything that signals "enterprise PM tool":

- Colored sidebars and tinted panels separating regions.
- Multi-color status badges scattered through every list.
- Heavy card grids of identical sized boxes.
- Decorative drop shadows on rectangles.
- Avatars and metadata stacked four-high on every row.

**Theme:** Light and dark are equal. Whichever the user picks should feel finished, not adapted. The OKLCH grayscale palette in `styles.css` is the foundation for chrome — `--foreground`, `--muted-foreground`, `--background`, `--accent`. The chromatic palette in `packages/shared/src/colors.ts` (`TAG_COLOR_WHEEL`, two OKLCH rings at fixed L/C) is the foundation for *user-assigned* color — tags today, anything categorical the user controls in the future. Don't introduce a brand hue and don't invent ad-hoc colors when the wheel already covers the space.

**Typography:** Geist (sans), Geist Mono (mono), Geist Pixel (display/decorative) are already loaded. Geist Sans for everything UI. Geist Mono for IDs, branches, slugs, code, anywhere "this is a literal." Geist Pixel exists for moments where the dithering brand thread surfaces — empty-state graphics, brand marks, occasional decorative labels — never for body text or running UI.

**The signature: dithering.** The brand mark itself is a dithered projection — stepped 1-bit-feeling shapes built from two greys (`#FEFEFE` foreground, `#807F7F` muted-foreground) on the surface color. That texture is the brand. Pull the same language through every graphic surface: empty states, illustrations, decorative motifs, marketing/landing surfaces, loading frames, hero blocks. Stick to ordered-dither (Bayer matrix) shading and the same two-grey vocabulary as the logo so everything reads as one family.

Functional UI controls (buttons, inputs, rows, menus) stay clean and modern — they never get the dither treatment. The two languages — clean type-driven UI and dithered graphic accents — work because they don't compete: the UI never asks for attention, so the graphics can carry weight.

### Design Principles

1. **Restraint first.** If a border, shadow, color, or animation isn't earning its place, delete it. The default answer to "should I add visual emphasis here" is no.
2. **Type and space carry hierarchy.** Not color, not chrome. Weight, size, and whitespace do the work that bordered cards would do in a Jira-style UI.
3. **Neutrals carry the chrome; color is a user-assigned signal.** UI surfaces (backgrounds, borders, text, controls, status badges, type icons) are neutral OKLCH grays — no brand hue. Color in the app is a *user* affordance, not a designer one: tags pull from the shared two-ring OKLCH wheel in `packages/shared/src/colors.ts` (inner ring L=0.78 C=0.07 for quiet pastels, outer ring L=0.7 C=0.16 as the default tag palette). When you build something new that needs categorical color, reuse `TAG_COLOR_WHEEL` instead of inventing fresh hues. Destructive red is the one chromatic UI exception and stays scarce.
4. **Dithering is the signature, and it lives in graphics.** The logo already speaks this language; everything graphic should extend it (empty-state illustrations, decorative motifs, marketing/landing surfaces, loading frames). Same two-grey vocabulary as the logo. UI controls — buttons, inputs, rows, menus — stay clean and don't get the texture.
5. **Light and dark are peers.** Every surface is reviewed in both. A choice that only works in one theme isn't done.
6. **Density without noise.** This is an engineer's tool — show information. But every row, badge, and metadata cluster has to justify itself. When in doubt, hide behind hover or progressive disclosure.
7. **Interaction craft is non-negotiable.** Press feel, hover asymmetry, optimistic mutations, variant-first composition — the rules in `CLAUDE.md` are the floor, not the ceiling.
8. **No capitalized headings, subheadings, or labels.** Sentence case only. Never `uppercase`/`tracking-wide` on rail dividers, section headers, popover titles, table column heads, pill labels, status indicators — any chrome text. The all-caps "Active / Planned / Completed / Tags / Recent / Status / Type / etc." pattern is a Jira-DNA tell and is forbidden. If a label needs visual separation from body text, lean on size, weight, or muted color — not capitalization. Acronyms (PR, ID, URL) keep their natural casing inside otherwise sentence-case strings; this rule is about *styling lowercase words into uppercase*, not about banning capital letters in proper nouns.
