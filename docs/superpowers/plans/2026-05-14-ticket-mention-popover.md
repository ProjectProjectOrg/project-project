# Ticket-mention preview popover — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the ticket-mention chip's bare link with a hover-preview / click-pin popover that shows the ticket's title, status/type/priority, first body line, assignees, and (when attached) branch/PR row, plus an explicit "view ticket" link.

**Architecture:** One new component (`TicketMentionCard`) plus a modification to `MentionChip`'s ticket branch that wraps its existing `Badge` in a base-ui `Popover.Trigger` rendered as a `Link`. The card subscribes to the existing `ticketAtom(ticketKey(...))`, which already merges list-cached metadata with on-demand body fetch — no new atom needed. Branch/PR row reuses `TicketGitChip`. User-mention chips and Lexical-editor chips are untouched.

**Tech Stack:** TanStack Router, base-ui Popover (`@/components/ui/popover.tsx`), `@effect-atom/atom-react`, paraglide i18n.

**Spec:** `docs/superpowers/specs/2026-05-14-ticket-mention-popover-design.md`.

**Branch:** `chore/T-57-ticket-mention-popover` (already created off `origin/main`, spec already committed).

**Testing note:** the frontend package has no test runner — only `bun run typecheck`. The spec's "component tests" cannot exist; this plan replaces them with typecheck + a manual verification checklist (Task 8). This is a deliberate divergence from the spec, recorded here.

### Task 2: Create `TicketMentionCard` skeleton

Stand up the file, wire the atom, render success-only with a single placeholder line. We'll add fields and other states in later tasks.

**Files:**
- Create: `packages/frontend/src/components/Lexical/TicketMentionCard.tsx`

- [ ] **Step 1: Create the file**

```tsx
import { Result, useAtomValue } from "@effect-atom/atom-react"
import { Link } from "@tanstack/react-router"
import { useMentionScope } from "@/mentions/scope"
import { ticketAtom, ticketKey } from "@/atoms/tickets"
import { m } from "@/paraglide/messages"
import type { TicketId } from "@projectproject/shared"

export function TicketMentionCard({ ticketId }: { ticketId: TicketId }) {
  const scope = useMentionScope()
  if (!scope) return null
  const result = useAtomValue(
    ticketAtom(ticketKey(scope.orgSlug, scope.slug, ticketId))
  )

  if (Result.isFailure(result)) {
    return (
      <div className="text-xs text-muted-foreground">
        {m.tickets_mention_card_not_available()}
      </div>
    )
  }

  if (!Result.isSuccess(result)) {
    return <CardSkeleton id={ticketId} />
  }

  const ticket = result.value

  return (
    <div className="space-y-2">
      <div className="text-xs font-mono text-muted-foreground">{ticket.id}</div>
      <div className="text-sm font-medium leading-snug line-clamp-2">
        {ticket.title}
      </div>
      <div className="border-t border-border pt-2 text-right">
        <Link
          to="/orgs/$orgSlug/projects/$slug/tickets/$id"
          params={{ orgSlug: scope.orgSlug, slug: scope.slug, id: ticketId }}
          className="text-xs text-muted-foreground transition-colors hover:text-foreground"
        >
          {m.tickets_mention_card_view_ticket()} →
        </Link>
      </div>
    </div>
  )
}

function CardSkeleton({ id }: { id: TicketId }) {
  return (
    <div className="space-y-2">
      <div className="text-xs font-mono text-muted-foreground">{id}</div>
      <div className="h-4 w-3/4 rounded bg-muted" />
      <div className="h-3 w-1/2 rounded bg-muted" />
    </div>
  )
}
```

### Task 4: Add first-body-line row

Strip the auto-prefixed `# Heading` and take the first non-empty line.

**Files:**
- Modify: `packages/frontend/src/components/Lexical/TicketMentionCard.tsx`

- [ ] **Step 1: Add the `firstBodyLine` helper at module scope**

Place above the `TicketMentionCard` export:

```tsx
function firstBodyLine(body: string | null | undefined): string | null {
  if (!body) return null
  for (const raw of body.split("\n")) {
    const line = raw.trim()
    if (!line) continue
    if (line.startsWith("#")) continue
    return line
  }
  return null
}
```

- [ ] **Step 2: Render the body line in the success branch**

After `<MetaRow>` and before the footer divider, add:

```tsx
{firstBodyLine(ticket.body) !== null ? (
  <p className="truncate text-xs italic text-muted-foreground">
    {firstBodyLine(ticket.body)}
  </p>
) : ticket.body === undefined ? (
  <div className="h-3 w-2/3 rounded bg-muted" />
) : null}
```

Rationale: `ticket.body` is `undefined` when the list-cached `TicketSummary` provided metadata but `ticketBaseAtom` hasn't resolved yet (the merge in `atoms/tickets.ts:73-92` leaves `body` only when the base atom fills it in). When it's `null` or `""`, the ticket genuinely has no body, so we show nothing. When it's a string, we render the first line.

Verify the assumption by looking at `TicketSummary` vs `TicketDetail` in `packages/shared/src/`. If `TicketSummary` doesn't carry `body` and `TicketDetail` does (as expected), the `undefined` branch is correct. If the merge actually leaves `body` as `null` while waiting, switch the skeleton condition to `result.waiting && ticket.body === null`.

### Task 7: Verify modifier-click pass-through

Base-ui's `Popover.Trigger` calls `preventDefault` on its click handler to suppress anchor navigation in favor of toggling the popover. We need Cmd/Ctrl/middle-click to still navigate.

- [ ] **Step 1: Manually test modifier clicks**

Start the dev server:

```bash

```

Navigate to a page that renders ticket mentions in markdown (e.g. a comment that mentions another ticket — pick any ticket on the dedicated ticket page with a mention in its description, or post a comment with `[T-12](mention:ticket/T-12)` syntax in the form).

Then:
- Cmd-click (macOS) or Ctrl-click (Win/Linux) the chip. Expected: new tab opens to the ticket page; popover does not appear.
- Middle-click the chip. Same expectation.
- Right-click → "Open in new tab". Same expectation.

- [ ] **Step 2: If modifier clicks open the popover instead, add a capture handler**

If any of the above failed (popover opened or nothing happened), modify the `render={<Link/>}` in `MentionChip.tsx` to include an `onClickCapture`:

```tsx
render={
  <Link
    to="/orgs/$orgSlug/projects/$slug/tickets/$id"
    params={{ orgSlug: scope.orgSlug, slug: scope.slug, id }}
    onClickCapture={(e) => {
      if (e.metaKey || e.ctrlKey || e.shiftKey || e.button === 1) {
        e.stopPropagation()
      }
    }}
    onMouseDown={(e) => e.preventDefault()}
  />
}
```

`stopPropagation` on the capture phase prevents base-ui's trigger from receiving the click, so the browser handles the anchor natively for modifier clicks. Plain clicks fall through and base-ui toggles the popover as before.
