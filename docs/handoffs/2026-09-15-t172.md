## Latest product decisions (override old ticket/spec text)

- Create status is in T-172, superseding existing-status-only. It plans a status with the Jira source name and creates it during hidden import, not on selection. Deterministic server-owned slugs, collision checks and deduplicated descriptors keep retries stable. Invalid names are not silently truncated.
- Only existing slug `done` is terminal in the current domain. New custom statuses are nonterminal even when styled like Jira Done; UI warns and offers mapping to existing Done. Do not silently introduce multiple terminal states.

- Earlier wizard steps are revisitable. Connect/Choose for a scanned job are read-only; navigation must not change source, rescan, configure or run. Forward validation remains required.
- Invite-and-connect is deferred to **T-173**, not a T-172 prerequisite. Pending invitations are not users; no placeholder identities or automatic linking. That follow-up needs acceptance/email/reconciliation design.
- No epic/milestone management UI in T-172. Import existing Group data underneath only.
- Explicit identity/restriction/tag-collision/attachment-skip choices; preserve all completed sprint history and require user resolution of competing active/future memberships.
- Hidden files/objects first; one PostgreSQL transaction publishes indexes and success. Failed/cancelled artifacts retained 30 days; successful archive stays with project.
- Personal Jira connection persists until explicit disconnect. Imported Jira comments always immutable, including linked native authors; historical bodies may exceed native 20k limits.
