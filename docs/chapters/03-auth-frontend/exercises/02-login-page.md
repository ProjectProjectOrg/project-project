# 02 — The login page

## Goal

Build a `/login` route that hosts a "Sign in with GitHub" button, using the Better Auth React client. After clicking, the user is bounced through GitHub OAuth and lands back on `/` with a session cookie.

## Concepts practiced

- File-based routing in TanStack Router (a new file = a new route, no manual registration).
- Calling Better Auth's React client from a component event handler.
- Using `meAtom` as a "should I redirect?" check inside a component.
- Why this page lives _outside_ `_authed` — and why that matters.

## Files you'll touch

- `packages/frontend/src/routes/login.tsx` — new file, stubbed for you.
- `packages/frontend/src/routeTree.gen.ts` — auto-regenerated by Vite/TanStack plugin. You don't edit it.

## Steps

### 1. Fill in the login page

Open `packages/frontend/src/routes/login.tsx`. The file's comment block has the full shape. Three things to write:

1. The imports.
2. `export const Route = createFileRoute("/login")(...)`.
3. `LoginPage`, including:
   - Read `meAtom`. If `Result.isSuccess`, return `<Navigate to="/" />`.
   - A click handler that calls `authClient.signIn.social({ provider: "github", callbackURL: "/" })`.
   - A button that triggers it.

### 2. The route tree

When you save `login.tsx` with the dev server running, the TanStack Router plugin regenerates `routeTree.gen.ts` to include `/login`. If it doesn't pick up the change:

```bash
bun run --filter @projectproject/frontend dev
```

(Stop and restart the dev server.) `routeTree.gen.ts` is gitignored conceptually but tracked in our setup; you may see it change in `git diff`. That's fine.

### 3. Verify

- Visit `http://localhost:5173/login` — see the button.
- Click it. You should be redirected to GitHub.
- After consent, you land back on `http://localhost:5173/` with a session cookie. The smoke-test home should now render your user JSON via `meAtom`.
- Visit `/login` _while signed in_ — you should be redirected to `/` immediately (the `Result.isSuccess` branch).

## Acceptance criteria

- [ ] `/login` renders without a console error.
- [ ] The button initiates a GitHub OAuth round-trip (Network tab shows POST to `/api/auth/sign-in/social`, then a navigation to GitHub).
- [ ] After signing in, returning to `/login` redirects to `/`.

## Hints

- `Navigate` and `createFileRoute` come from `@tanstack/react-router`. If autocomplete doesn't suggest them, double-check the import path.
- The React client doesn't need `await` to actually sign in — it kicks off the redirect itself. But `await`-ing it lets you `try/catch` the rare cases where the POST fails before the redirect (e.g. backend not running). Either is fine.
- If the button click does nothing, open Network tab and look at the response of `POST /api/auth/sign-in/social`. A 200 with `{ url, redirect }` means Better Auth is happy; the React client should then navigate. A 4xx/5xx means the backend or OAuth config has an issue — check `BETTER_AUTH_URL` and `GITHUB_CLIENT_ID`.
- Don't add styling beyond the bare minimum. The `polish`/`typeset` skills will earn their keep in a later chapter when there's actual UI to polish.
