# Test audit — 22 October 2026

Baseline: `53ca88a6f2b659a86167c093e0c88ca25e8f2c54` (`main`).

## Agreed scope

Remove React component-rendering tests; retain domain logic, API contracts, atoms, hooks, and headless editor tests. This intentionally retires DOM interaction, component wiring, visual styling, and rendered accessibility coverage. The remaining helper tests are not equivalent proof of those removed integration contracts.

The suite still uses its existing jsdom environment for hooks and headless DOM consumers. No real-browser project or new dependency was introduced. Unlike T3 Code's environment ban, this policy bans component-renderer imports: Testing Library `render` (including aliases and subpaths), direct `react-dom`, and `react-test-renderer` in test files. `renderHook` and provider wrappers remain supported. AGENTS.md records the scope and forbids hiding renderers behind helpers.

## Follow-up work

All 323 baseline files are accounted for exactly once across the five ledgers. These findings retain their existing tests in this PR. They need focused repairs or assertion transfers, rather than blanket removal.

1. **Make negative controls reach the intended guard.** Jira `Manifest.test.ts` has invalid subtask/missing-field fixtures that can fail before the condition named by the test. `Import.test.ts` leaves a conflicting destination reservation before a stale-attempt check. `ticketGitStatePlanner.test.ts` combines archive, default-branch, already-linked, and ambiguity guards. Start from valid controls and assert the exact failure; temporarily removing each intended guard should make its test fail.
2. **Assert structured defects in auth mapping.** Backend invitation/org tests often check only that a pretty-printed failure omits one error name. Assert the defect channel and original error instead. The accepted-invitation fixture has a future expiry and does not establish the expired-and-already-accepted contract; reproduce that combination before proposing a product fix.
3. **Make concurrency fixtures demonstrate overlap.** Keyed-lock/domain-lock tests need explicit acquisition/release handshakes. Preserve domain key/namespace isolation alongside generic mutex mechanics. Completion-only Deferred/join tests can be meaningful and should not be removed merely for lacking `expect`.
4. **Separate optimistic confirmation from refetch.** Some sprint/library mutation fixtures return the same prediction from POST and GET, hiding premature release of the confirmed result. Control responses independently while retaining rollback, overlapping-edit, per-ticket error, and cross-view invalidation coverage.
5. **Retire the unreachable Jira V1 layer in a focused follow-up.** Old import/context, staged-document, attachment/member/environment, and report/archive adapters have no live consumers. Before removing their wrapper tests, transfer unique tag/status/member/author/image/sprint-membership assertions into the artifact-backed `PublicationPlan.test.ts` keepers. Preserve live publication draft/reference/text/media/preflight/scan helpers and actual SQL atomic exposure/rollback tests. Seven direct-delete recommendations in this lane remain with that coherent cleanup.
6. **Consolidate duplicate ticket orchestration fixtures.** The two split rollback scenarios fail at the same retained-original upsert; combine restoration and new-file-removal assertions. `Tickets.test.ts` repeats sorting/filtering/counting implemented by its own fake index; keep service forwarding, viewer substitution, response mapping, pagination and permission contracts, with query semantics owned by `TicketIndexLive.postgres.test.ts`.
7. **Move SQL-shape checks only after proving the behavioral keeper.** Title sort/cursor collation tests can move to real Postgres ordering coverage, but descending cursor traversal and a collation-sensitive mutation control must exist before removing generated-SQL assertions.
8. **Strengthen weak pure assertions.** Avoid self-derived slug inventories, empty-collection `.every` checks, scalar-manufactured aspect ratios, and finite-size tests that only assert positivity. Keep compile-time `@ts-expect-error` contracts while removing their tautological runtime wrappers in a dedicated change.
9. **Repair security fixtures before relying on their names.** `projectMembers.postgres.test.ts` must seed a connected GitHub repository and prove a privileged role sees it before testing client redaction. `Groups.test.ts` must seed a real sprint and require `Forbidden`, rather than accepting `NotFound`. `OAuthApplications.test.ts` must seed another user’s access/refresh tokens and assert they survive revocation. The malformed-markdown webhook case must fail `TicketDocs.update`, which the owner actually calls, rather than `read`. These are gaps in test evidence, not confirmed production vulnerabilities.
10. **Strengthen SQL and pagination oracles.** Attachment SQL tests need operative values and conjunctions, not column-name presence alone. Activity pagination must follow cursors and deliberately seed equal timestamps; concurrency tests must force overlapping IO. Retain real hidden-resource and orphan-project database controls.
11. **Treat cluster initialization as a separate reliability issue.** Reproduce the first-start table-creation race on a fresh isolated database. The successful initialized-database run is not evidence that concurrent schema creation is safe.

Detailed per-declaration ledgers and independent preservation reports were produced during the audit. This report records the applied scope and actionable follow-ups; it does not claim that every repair/consolidation recommendation has been implemented.
